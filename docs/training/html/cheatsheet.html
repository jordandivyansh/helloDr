API map

Method / pathAccess and purpose
GET /api/healthPublic liveness
GET /api/clinicPublic clinic configuration
POST /api/auth/loginPublic credentials → session
POST /api/auth/registerPublic parent registration + consent
GET /api/auth/meSigned-in user
POST /api/auth/logoutDelete user's sessions
GET /api/childrenScoped child list
POST /api/childrenParent creates own child
GET /api/appointmentsScoped visit list
POST /api/appointmentsAuthorized child booking
PATCH /api/appointments/:idParent cancellation or doctor state change
GET /api/slots?day=YYYY-MM-DDSigned-in availability lookup
POST /api/slotsDoctor publishes time
GET /api/records/:childIdAuthorized child records
POST /api/records/:childId/notesDoctor publishes note
POST /api/records/:childId/vaccinesDoctor enters vaccine plan
PATCH /api/vaccines/:idDoctor records administration
POST /api/assistant/briefDoctor requests deterministic summary

POST/PATCH bodies are JSON. Writes require matching Origin. Private routes require the session cookie. Some reads also create audit events.

Never confuse these

  • Responsive web UI ≠ native mobile app.
  • Tenant columns ≠ complete multi-tenant SaaS.
  • Structured brief ≠ AI model integration.
  • TypeScript type ≠ runtime validation.
  • Hidden button ≠ server authorization.
  • Build success ≠ deployment success.
  • Test pass ≠ proof of production capacity or compliance.
  • Local database ≠ hosted database.
